# Synapse Evolution: owner review before any source promotion

**Development-only Stage 3.** This milestone adds a read-only Evolution tab
to native Synapse Control, together with a source/hash-bound owner-review gate.
It does **not** make the model a root user, auto-merge changes, change trusted
boot code, deploy cloud services, or install an update.

## The real experiment being reviewed

This narrow initial gate reviews only one known model-assisted change:

- Qwen2.5-Coder-0.5B-Instruct at the pinned public revision
  ea99d3edbfc6669b8b24cbaa6a98ec0e857f0155, running locally on a CI CPU.
- Run 36150437142: its original proposal was rejected (list replacement).
- Run 36150869207: after real feedback, the model supplied the corrected
  **one statement** self.events.clear(). A trusted template supplied the
  keyword-only opt-in parameter and conditional. The full source patch and
  tests must never be described as wholly model-authored.
- Run 36151721750: separate baseline and candidate boots on QEMU TCG with
  networking disabled, and fixed independent status, doctor and debugger
  regressions passed in both guests. The candidate's optional reset passed.
- Run 36154999097: the exact committed candidate in draft PR #35 passed
  its full source, Beast browser, built-ISO, live-boot and installed-VM
  validation suite.

These are bounded facts. They do not establish AGI, consciousness, the
security of arbitrary model code, verified model origin in all environments,
or measured system performance improvements.

## Owner review verification

Workflow synapse-evolution-owner-review.yml downloads the exact historical
two-VM artifact via GitHub Actions, independently queries the known successful
candidate CI run from GitHub, checks the exact current debugger source
SHA-256, reconstructs the baseline and confirms its source SHA-256,
and revalidates historical original/corrected model response SHA-256s,
versioned source/patch receipts and both separate guest check documents.
Tampering with any one of the evidence layers fails closed.

The workflow archives an owner-inspection bundle containing:

- REVIEW_BUNDLE.json: origin and narrow verified prior test outcome.
- ROLLBACK_PREVIEW.diff: **informational only**; never auto-applied.
- ORIGINAL_DEBUGGER_BASELINE.py.txt: byte-identical prior source.
- ORIGIN_HANDOFF.json, COMPARISON.json, STAGED_PATCH_RECEIPT.json and
  ACTUAL_MODEL_CORRECTION.txt: historical prior evidence, not fabricated.
- VERIFIED_CANDIDATE_CI.json and SHA256SUMS.

Inspect the actual pinned GitHub run as well as the bundle. An unsigned JSON
import by itself is never an authorization token or an independently
authenticated GitHub attestation.

For local developer review with a downloaded, extracted official evidence
artifact and a separately downloaded exact candidate CI run JSON:

    PYTHONPATH=src python3 -m synapse.evolution_review \
      --artifact /path/to/real-VM-artifact --repo . \
      --ci-run-json /path/to/exact-CI-run.json \
      --output /tmp/synapse-owner-review

The output folder must be outside the source repository and initially empty.

## Native Synapse Control UI

Open Synapse Control, select **Evolution**, and choose a local REVIEW_BUNDLE.json.
The tab displays a bounded, plain-text **reported** summary. It runs no
model, shell, privileged helper, updater or remote fetch; opening a file
cannot approve changes. It visibly distinguishes an imported unsigned JSON
from evidence actually verified by the CI workflow.

The production machine remains unchanged. PR #36 adds this UI and verifier
on top of draft PR #35; neither PR is merged into main. The next required
gate is a full build and VM smoke of the *new* review-UI code. Passing the
earlier candidate's run is not a substitute for testing the updated image.

## Conditions for later controlled promotion

1. Preserve source, exact original and corrected model outputs, full
   reproduction parameters, original bytes and hash-bound staged patch.
2. Repeat independent baseline/candidate VM evaluation and full tests
   with a trusted test manifest not generated by the candidate model.
3. Have an independent policy authority verify both artifacts and allowed
   scope, then submit the exact reviewed branch as a **draft PR**.
4. Require explicit owner approval and retain backup, signed release checks
   and a tested rollback path before any real OS update.
5. Never pass Beast/COSMOS memory, credentials, permissions, model-specific
   hidden state or production deployment keys into the candidate VM.

MODEL ≠ MEMORY. MODEL ≠ STATE. MODEL ≠ AUTHORITY.
